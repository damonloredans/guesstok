# Guesstok Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A web page that runs the whole guessing game by itself (rounds, pixel reveal, guessing, scoring, daily leaderboard), fed by a swappable event source, so TikTok Live can be connected later.

**Architecture:** Pure game logic lives in small ES modules under `src/` that take plain values and return plain values, so Node's built-in test runner covers them. A thin browser layer (`pixel.js`, `ui.js`, `main.js`) renders a 3D glTF model at a very low resolution and scales it up with no smoothing, and draws the overlay. Guesses, likes and gifts all enter through one event bus.

**Tech Stack:** Plain HTML and ES modules, Three.js 0.160.0 from the jsDelivr CDN via an import map (no build step, no bundler), `node:test` for tests (Node 18+, the machine has Node 26), `npx http-server` to serve the folder. (shortcut: CDN import means the page needs internet, so vendor Three.js into the repo if the stream machine is ever offline.)

**Spec:** `docs/superpowers/specs/2026-11-03-guesstok-design.md`

## Global Constraints

- Round length 15 seconds, a stage every 3 seconds, 5 stages (stage 0 is the most pixelated, stage 4 almost clear).
- Items are `.glb` files in `models/`. Every number below is a setting in `src/settings.js`, never hard-coded elsewhere.
- Guess matching: case-insensitive, plurals of an accepted answer are correct, typos are not.
- Points by stage: 5, 4, 3, 2, 1, times the guesser's multiplier. A viewer can win a round once.
- Gift: +1 multiplier each, 30 seconds on its own timer, multiplier is 1 plus the viewer's gifts sent in the last 30 seconds, no cap, every gift counts the same.
- Likes make the stage advance sooner: stage is time stage plus one for every `likesPerStage` likes, clamped to the last stage.
- Leaderboard resets every 24 hours at a fixed hour set in settings. It is stored in the browser.
- Vertical 9:16 layout. Hologram scanner look (dark, thin cyan lines) kept entirely in `src/theme.css`. On-screen text at least 11px.
- Game logic reads events `guess {user, text}`, `like {user, count}`, `gift {user, count}`. The TikTok connector is out of scope.
- A credits file lists every model pack, author and licence. The Gundam model, duplicate files (names ending in a random code) and generic house parts (doors, windows, ceiling lights, drawers) stay out of the item list.

## Review Focus

Most likely to bite first. Each line has a test in the task named in brackets.

- A model that fails to load must skip that item and start the next round, not freeze the stream. [Task 6, Task 7]
- The same viewer sending the correct answer twice in one round gets points once. [Task 4]
- A guess arriving after the round ends, during the pause, is ignored and does not score. [Task 4]
- A huge batch of likes in one event cannot push the stage past the last stage. [Task 4]
- Reloading the page after the daily reset time must not show yesterday's scores, and reloading before it must keep today's. [Task 5]

## File Structure

- `index.html`: page shell, import map, loads `src/theme.css` and `src/main.js`.
- `src/settings.js`: all tunable numbers.
- `src/events.js`: the event bus.
- `src/match.js`: answer matching.
- `src/score.js`: points and the gift multiplier.
- `src/round.js`: one round's state, and picking the next item.
- `src/leaderboard.js`: daily leaderboard over an injected store.
- `src/items.json` and `src/credits.js`: item data and credits.
- `src/pixel.js`: Three.js scene and pixel stage rendering.
- `src/ui.js`: overlay (banner, floating guesses, leaderboard, results) and the dev panel.
- `src/main.js`: wires it together and runs the loop.
- `tests/*.test.js`: one test file per logic module.

### Task 4: Round engine

**Files:** Create `src/round.js`, `tests/round.test.js`

**Interfaces:**
- Consumes: `isCorrect` (Task 2), `pointsFor` (Task 3), `settings`.
- Produces:
  - `createRound({item, startedAt: number, settings}): Round` where `Round` has `stage(now): number`, `addLikes(count: number): void`, `guess({user, text, now, multiplier}): {correct: boolean, points: number}` (points is 0 when wrong, a repeat winner, or the round is over), `isOver(now): boolean` (true at `startedAt + roundSeconds*1000`), `winners: {user: string, points: number, stage: number}[]` in the order they won.
  - `createPicker(items, rng?: () => number): { next(roundNumber: number): Item }` using `settings.difficultyRamp`, and never returning the same item twice in a row when more than one is available (it remembers the last pick).

- [ ] **Step 1: Write failing tests**: `stage rises every 3 seconds` (0 at 0, 1 at 3000, 4 at 12000, stays 4 at 14999); `likes push the stage ahead` (with `likesPerStage` 100, 100 likes at t=0 gives stage 1, 250 likes gives stage 2); `a huge like batch cannot pass the last stage` (`addLikes(1e9)` gives stage 4); `correct guess scores by stage and multiplier` (item Pizza, at t=7000, multiplier 2: `{correct:true, points:6}` because stage 2 is 3 points); `wrong guess scores nothing`; `a viewer scores only once per round` (second correct guess returns `{correct:true, points:0}` and `winners` has one entry for them); `guess after the round ends scores nothing` (at t=15000 returns `{correct:false, points:0}`); `picker uses easy items first` (round 1 only returns easy items, with a seeded `rng`); `picker does not repeat the previous item back to back`.
- [ ] **Step 2: Run** `npm test`. Expected: FAIL.
- [ ] **Step 3: Implement** `createRound` and `createPicker` as specified. Time stage is `floor((now - startedAt)/stageSeconds/1000)`; effective stage is `min(stages-1, timeStage + floor(likes/likesPerStage))`.
- [ ] **Step 4: Run** `npm test`. Expected: PASS.
- [ ] **Step 5: Commit** `git add src/round.js tests/round.test.js && git commit -m "feat: round engine and item picker"`

### Task 9: Wire it together and verify

**Files:** Create `src/main.js`, `README.md`; modify `index.html` if needed
